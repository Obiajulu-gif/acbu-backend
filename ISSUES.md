# Backend – Known Issues

Issues found in the ACBU backend API server (Express/TypeScript, Prisma/PostgreSQL, MongoDB, RabbitMQ, Stellar/Soroban integration). Add new items below as numbered list entries.

---

## Critical

1. **Missing input validation on `fintech_tx_id` in mint flow** – src/controllers/mintController.ts: `fintech_tx_id` is accepted from client input but the contract-layer duplicate check requires the backend to enforce uniqueness first. A malicious or buggy client can replay the same TX ID, causing mint failures and support load.
2. **Stellar secret key in application memory** – src/services/wallet/stellarSecretService.ts: Stellar secret keys for the platform wallet are loaded into memory at startup and held for the process lifetime. A memory dump or debugging endpoint leaks full signing keys with no rotation.
3. **No idempotency enforcement on mint/burn/transfer** – src/controllers/mintController.ts, src/controllers/burnController.ts, src/controllers/transferController.ts: None of the write endpoints accept or validate an idempotency key. Network retries produce duplicate transactions that the contract may or may not reject, leading to double-spend risk.
4. **RabbitMQ message loss on unhandled rejection** – src/jobs/: Several event consumer jobs use `channel.consume()` without `noAck: false` or manual acknowledgment. If the consumer process crashes mid-handling, the message is lost and the event (mint, burn, transfer) is never recorded.
5. **PII written to logs in error paths** – src/controllers/authController.ts, src/services/kyc/: Error messages include raw user input (passcodes, ID numbers, phone numbers) when `LOG_LEVEL=debug`. Production debug logging would leak PII to log aggregators.
6. **No request body size limit on file upload endpoints** – src/controllers/kycController.ts: KYC document upload endpoints lack `express.json({ limit })` or `body-parser` size limits. An attacker can send multi-GB payloads and exhaust server memory.
7. **Prisma raw queries without parameterization** – src/services/: Any use of `prisma.$queryRaw` or `prisma.$executeRaw` with template literals opens SQL injection if user input is interpolated instead of using `Prisma.sql` tagged templates.
68. **No database write-ahead log (WAL) backups configured** – src/config/database.ts: PostgreSQL WAL archives are not configured for point-in-time recovery. A storage failure on the primary database results in permanent data loss for all transactions since the last full backup.
69. **Fintech partner API keys committed to source control** – src/services/flutterwave/client.ts, src/services/paystack/client.ts: Partner API secrets may be checked into git history. Rotating leaked keys requires coordinated deployment across multiple environments.
70. **Prisma migration history table not replicated to read replicas** – prisma/migrations/: The `_prisma_migrations` table is not replicated to read replicas. If the primary fails and a replica is promoted, the new primary has no migration history and `prisma migrate deploy` may re-apply migrations or fail.
71. **Session token in query string for WebSocket upgrade** – src/services/websocket/: WebSocket connections may pass auth tokens in the query string. Proxy servers, load balancers, and CDNs log query strings, leaking session tokens to access logs and third-party services.
72. **No column-level encryption for KYC PII fields** – prisma/schema.prisma: KYC data (national ID numbers, passport scans, biometric hashes) are stored as plaintext in PostgreSQL. A database backup or replica exfiltrates identifiable personal data in clear text.

## High

8. **No circuit breaker on fintech partner HTTP calls** – src/services/flutterwave/client.ts, src/services/paystack/client.ts, src/services/mtn-momo/client.ts: Direct `axios` calls to external fintech APIs have no timeout, retry budget, or circuit breaker. A hung partner API blocks the Node.js event loop and cascades to all requests.
9. **Event listener silently stops on Stellar RPC disconnect** – src/services/stellar/eventListener.ts: The Soroban event stream does not auto-reconnect or emit a health metric on disconnect. Missed events (mint, burn, loan, escrow) create permanent gaps in the off-chain audit trail.
10. **No transactionality across DB + blockchain writes** – src/services/contracts/acbuMinting.service.ts: Mint flow writes to PostgreSQL (tx record) and submits a Stellar transaction. If the DB write succeeds but the Stellar tx fails, the DB shows a transaction that never happened on-chain. No compensation logic exists.
11. **Missing rate limit on 2FA and passcode endpoints** – src/middleware/rateLimiter.ts: The rate limiter may not apply to `/auth/2fa`, `/auth/signin`, or `/auth/passcode/reset` with per-user keys. Brute-force of 2FA tokens and passcodes is possible at line speed.
12. **Refresh token stored without family tracking** – src/services/auth/authService.ts: If refresh tokens are implemented, they lack token-family rotation. When a refresh token is used, the entire family should be invalidated to detect token theft. Without this, a stolen refresh token is usable indefinitely.
13. **Cache keys built from unsanitized user input** – src/utils/cache.ts: If cache keys are constructed from user-supplied parameters (e.g., `rate_${currency}`), an attacker can inject delimiters and pollute or poison cache entries shared across users.
14. **Missing `helmet` CSP or permissive defaults** – src/index.ts: `helmet()` is used but `contentSecurityPolicy` may be disabled or set to defaults that allow `unsafe-inline`. The backend serves API responses but may also serve error pages with inline scripts.
15. **MongoDB connection not pooled or retried** – src/config/mongodb.ts: MongoDB connection failures at startup may crash the process rather than retrying with exponential backoff. Transient network blips take down the entire API.
16. **Swagger UI exposed in production without auth** – src/config/swagger.ts, src/routes/: `/api-docs` may be mounted with `swagger-ui-express` in all environments. Exposed API documentation reveals internal endpoint structure to attackers.
73. **Prisma Accelerate connection timeout not aligned with upstream timeout** – src/config/database.ts: Prisma Accelerate's connection timeout may be shorter than the upstream PostgreSQL timeout. Queries cancelled by Accelerate mid-execution leave PostgreSQL connections in `idle in transaction` state, draining the connection pool.
74. **RabbitMQ connection heartbeat not configured** – src/config/rabbitmq.ts: The AMQP connection heartbeat interval is not explicitly set. Network appliances that drop idle TCP connections after 60 seconds cause silent disconnects not detected until the next publish.
75. **No database connection pool monitoring metrics** – src/config/database.ts: Prisma connection pool utilization, wait time, and acquisition latency are not exposed as Prometheus metrics. Pool exhaustion is detected only when requests start returning `P1001` errors.
76. **MongoDB change stream cursor not resumable after restart** – src/config/mongodb.ts: MongoDB change stream consumers use a fixed resume token stored in memory. On process restart, the consumer replays from the beginning or misses events, depending on whether `startAtOperationTime` is set.
77. **Fintech webhook signature timestamp not validated against clock drift** – src/controllers/webhookController.ts: Webhook signature verification may not check the timestamp header against server time. Replay attacks from within the allowed window (±5 minutes) are accepted.
78. **OTP/TOTP rate limiter bypassable via case variation of email** – src/controllers/authController.ts: Rate limiting on OTP requests may key on the raw email string. An attacker sends `user@gmail.com`, `User@Gmail.com`, `USER@GMAIL.COM` to triple their rate limit budget.
79. **`Access-Control-Allow-Origin` reflects request origin without whitelist** – src/middleware/cors.ts: CORS middleware may reflect any `Origin` header back in `Access-Control-Allow-Origin`. This allows any website to make credentialed requests to the API, enabling CSRF-style attacks.
80. **No request correlation ID generated if client doesn't send one** – src/middleware/correlation.ts: The correlation ID middleware may rely on the client sending `X-Correlation-ID`. If the header is absent, logs have no way to trace a request through multiple microservices.
81. **Prisma `interactiveTransactions` not enabled for batch operations** – src/config/database.ts, src/services/salary/salaryService.ts: Salary batch processing may use multiple separate Prisma writes without an interactive transaction. A failure mid-batch leaves some salary records committed and others not, with no rollback mechanism.
82. **Stellar account merge not protected by multi-signature or timelock** – src/services/stellar/client.ts: If the platform's Stellar account supports `account_merge`, a compromised backend can merge the entire asset pool into an attacker's account. Merge should require multi-sig or be disabled entirely for the treasury account.
83. **Email verification tokens generated with insufficient entropy** – src/services/email/emailService.ts: Email verification tokens may use `Math.random()` or a short `crypto.randomBytes(8)` that is brute-forceable. An attacker can verify any email address by guessing the token.
84. **No graceful degradation when Redis cache cluster is partitioned** – src/services/cache/redisService.ts: When Redis cluster experiences a netsplit, the service may throw unhandled `MOVED` or `ASK` errors. All cache-dependent endpoints (rate lookups, session validation) fail instead of falling back to the database.
85. **`Bunyan` or `Pino` logger not configured with log level per-transport** – src/config/logger.ts: All log levels go to all transports. Debug-level logs from `stellar-sdk` flood the production log aggregator, obscuring genuine errors and increasing log ingestion costs.
86. **No schema validation on RabbitMQ message bodies before publishing** – src/jobs/producers/: Message producers may publish objects that don't match the consumer's expected schema. Malformed messages accumulate in queues with no DLQ and block all subsequent message processing.
87. **`GraphQL` playground or introspection enabled in production** – src/graphql/ (if present): If the API exposes a GraphQL endpoint, the playground and schema introspection may be enabled in all environments, leaking the full API schema to attackers.

## Medium

17. **Prisma Accelerate connection pool exhaustion** – src/config/database.ts: If using Prisma Accelerate, connection limits are per-region. Burst traffic during salary runs or rebalancing events can exhaust the pool, returning `PrismaClientKnownRequestError` to all users.
18. **Missing index on `Transaction.createdAt` for history queries** – prisma/schema.prisma: The `Transaction` model has `@@index([userId])` but may lack a composite index on `(userId, createdAt DESC)`. Transaction history pages do full table scans under load.
19. **Missing index on `OracleRate.currency + timestamp`** – prisma/schema.prisma: Rate queries filter by currency and sort by timestamp. Without a covering index, rate lookups degrade linearly as rate history grows.
20. **No dead-letter queue for failed RabbitMQ messages** – src/jobs/: Failed event processing (malformed event, contract reverted) discards the message. There is no DLQ to inspect, replay, or alert on persistent failures.
21. **Oracle update job runs on a fixed interval without jitter** – src/jobs/scheduler/: If multiple backend instances run the oracle update cron simultaneously (no leader election), they produce duplicate rate submissions and stomp each other's on-chain state.
22. **Fintech webhook signature verification is mock/stub** – src/services/fintech/: If `simulated.ts` is used in production, webhook payloads from Flutterwave/Paystack are not cryptographically verified, allowing forged deposit confirmations.
23. **`depositFromBasketCurrency` silently accepts unknown currencies** – src/controllers/mintController.ts: If a currency code is not in the supported basket list but passes Zod validation, it reaches the conversion layer and throws a 503. A 400 with a clear "unsupported currency" message should be returned instead.
24. **`getAcbuUsdRate` calls DB on every mint request** – src/services/rates/: Each mint operation fetches the latest `AcbuRate` from PostgreSQL. Under 100+ concurrent mints, this creates a thundering-herd on the rates table. A short in-memory TTL cache or read replica would reduce load.
25. **No schema versioning for event payloads** – src/jobs/eventListeners/: Contract events (MintEvent, BurnEvent) parsed by backend listeners have no `version` field. A contract upgrade that adds fields will break the listener with silent parse failures.
26. **`salaryService` processes batches synchronously** – src/services/salary/salaryService.ts: Processing a payroll of 500 employees in a serial loop may exceed request timeout. Partial failures mid-batch leave some employees paid and others not, with no rollback or resume point.
27. **No retry with backoff on Stellar `tx_bad_seq`** – src/services/stellar/client.ts: If the Stellar account sequence number drifts (e.g., concurrent mint submissions), the SDK returns `tx_bad_seq`. The code should reload the sequence and retry once before failing.
28. **KYC validator rewards calculable without on-chain verification** – src/services/kyc/: Validator reward amounts are computed off-chain and may not be verifiable against the smart contract `admin_drip_demo_fiat` or mint amounts. A bug in reward math could overpay or underpay validators irreversibly.
29. **Audit trail not immutable at the DB level** – prisma/schema.prisma: The `AuditTrail` table relies on application code to never UPDATE or DELETE rows. Missing a DB-level trigger or row-level security policy means a compromised app or direct DB access can alter audit history.
30. **2FA challenge tokens lack `jti` uniqueness enforcement** – src/utils/jwt.ts: (Partially addressed by B-066) — Even with `jti`, the backend does not maintain a deny-list or bloom filter of recently used tokens. A stolen token used within its 5-minute window is not detected as a replay.
88. **Prisma `$transaction` timeout too short for bulk inserts** – src/services/ledger/ledgerService.ts: Ledger entry creation within a transaction may time out on batches > 100 entries. The client receives a timeout error but the transaction may have partially committed.
89. **No database connection retry with jitter on startup** – src/config/database.ts: All instances reconnect to the database at the same interval after a crash. The thundering herd on database connection slots causes cascading connection rejections.
90. **Stellar fee bump transactions not supported for stuck operations** – src/services/stellar/client.ts: If a mint/burn transaction is stuck in the mempool due to low fees, there is no mechanism to submit a fee-bump transaction. The user's operation appears "pending" indefinitely.
91. **`exchangeRateService` does not cache negative responses** – src/services/rates/exchangeRateService.ts: When an external rate API returns an error (5xx, timeout), the error is not cached. Every subsequent request retries the failing API, amplifying load on an already degraded service.
92. **No pagination token encryption in cursor-based pagination** – src/middleware/pagination.ts: Cursor-based pagination encodes the raw database ID in the cursor string. Users can decode and manipulate cursors to access rows outside their authorization scope (IDOR via pagination cursor).
93. **Webhook retry logic does not implement exponential backoff** – src/services/webhook/outboundWebhookService.ts: Outbound webhooks to fintech partners retry at a fixed interval. During partner outages, this floods the partner with requests instead of backing off and preserving rate-limit budget.
94. **No `If-Match` / `ETag` support for optimistic concurrency on wallet operations** – src/controllers/walletController.ts: Wallet balance updates are not conditioned on an ETag or version number. Two concurrent requests (e.g., a transfer and a sweep) may both read the same balance and both write, causing lost updates.
95. **`date-fns` or `moment` timezone conversion uses fixed UTC offset** – src/utils/dateUtils.ts: Date formatting may use a hardcoded offset or `Date.toISOString()` without considering the user's actual timezone preference. Business-day calculations for salary runs and withdrawal delays are off by one day in edge timezones.
96. **No request body decompression handling** – src/middleware/bodyParser.ts: The API does not handle `Content-Encoding: gzip` on request bodies. Mobile clients that compress large uploads (transaction batches, KYC documents as base64) receive 413 or parse errors.

99. **`ioredis` or `redis` client does not handle `READONLY` errors on replica failover** – src/services/cache/redisService.ts: During Redis Sentinel failover, the promoted replica initially returns `READONLY` errors. The client does not retry or reconnect, causing cache write failures until the connection is re-established.
100. **No API response time histogram by endpoint** – src/middleware/metrics.ts: Response time is tracked as a simple counter/gauge rather than a histogram with percentile buckets (P50, P95, P99). Slow endpoints with sparse high-latency outliers are invisible in average-based monitoring.
101. **`multer` or file upload middleware stores uploads in memory before validation** – src/controllers/kycController.ts: File upload middleware may buffer the entire file in memory before checking file type, size, or virus scan results. A 100MB zip bomb exhausts the Node heap before validation runs.
102. **No `Cache-Control` or `Surrogate-Control` headers on API responses** – src/middleware/cacheHeaders.ts: API responses for semi-static data (currency list, supported countries, fee schedules) carry no cache headers. CDNs cannot cache them, and every client request hits origin.
103. **`jsonwebtoken` `verify` does not check `typ` header for JWT confusion** – src/middleware/authMiddleware.ts: JWT verification may not validate the `typ` header is `JWT`. An attacker with a valid OAuth access token from the same issuer can use it to authenticate as a user (JWT confusion attack).
104. **No database read/write split for reporting queries** – src/services/reports/reportService.ts: Heavy reporting queries (monthly statements, audit exports, regulatory reports) hit the primary write database, contending with transactional workloads for CPU and I/O.
105. **`node-cron` or `node-schedule` jobs run on all instances without leader election** – src/jobs/scheduler/: Scheduled jobs (daily interest accrual, monthly fee collection) execute on every API instance simultaneously. Without distributed locking, duplicate jobs process the same data and cause double charges.
106. **No idempotency key timeout or cleanup for abandoned operations** – src/services/idempotency/idempotencyService.ts: Idempotency keys stored for duplicate prevention have no TTL. The idempotency store grows unboundedly, eventually causing storage exhaustion and lookup latency degradation.
107. **`express-async-errors` not patched or unhandled promise rejections crash the process** – src/index.ts: Express 4 does not natively catch async errors in route handlers. Without `express-async-errors` or a wrapper, rejected promises in handlers crash the process with `unhandledRejection`.
108. **No circuit breaker on Stellar Horizon RPC calls** – src/services/stellar/client.ts: Direct `axios` calls to Horizon have no circuit breaker. When Horizon is degraded (high latency, 503), every API request waits for the Horizon timeout (default 30s), saturating the Node.js event loop.
109. **Prisma model `@@unique` constraints not covered by database-level unique indexes** – prisma/schema.prisma: Some composite unique constraints may only exist at the Prisma level. If a concurrent insert bypasses Prisma (e.g., direct DB connection, migration script, replica), duplicates enter the database with no integrity error.
110. **`nodemailer` transport pool not monitored for connection leaks** – src/services/email/emailService.ts: Nodemailer SMTP connections may leak if `transport.close()` is not called after batch sends. The SMTP server eventually rejects new connections when the pool is exhausted.


## Low

31. **`Prisma.$disconnect()` not called on SIGTERM** – src/index.ts: Graceful shutdown may not await `prisma.$disconnect()`, causing connection leaks on container restarts in Kubernetes.
32. **`helmet.hsts` missing or misconfigured** – src/index.ts: HSTS header may have a `maxAge` too low (< 1 year) or miss `includeSubDomains`, weakening protection against SSL stripping.
33. **Health check endpoint returns 200 before RabbitMQ/MongoDB are ready** – src/controllers/healthController.ts: The health check may report "healthy" before all infrastructure connections are established, causing the load balancer to route traffic to a partially-initialized instance.
34. **Swagger JSON spec not versioned alongside API changes** – swagger.json: The OpenAPI spec is manually maintained and can drift from actual route handlers. No CI step asserts that the spec matches the Zod schemas used in validation middleware.
35. **No structured error codes in API responses** – src/middleware/errorHandler.ts: Errors return HTTP status + message string but no machine-readable `errorCode` enum. SDK consumers must parse human-readable strings to determine error type.
36. **`express-rate-limit` uses in-memory store by default** – src/middleware/rateLimiter.ts: Rate limit counters live in process memory. Multiple instances behind a load balancer each have independent counters, allowing an attacker to multiply their rate limit by the instance count.
37. **`s3Service` uploads with public-read ACL by default** – src/services/storage/s3Service.ts: KYC document uploads may use `ACL: 'public-read'`. PII documents (passports, ID cards) must never be publicly accessible, even for a short window.
38. **No Content-Type enforcement on webhook endpoints** – src/controllers/webhookController.ts: Webhook endpoints may not enforce `Content-Type: application/json`. An attacker sending `multipart/form-data` or `text/xml` could bypass body parsing middleware and trigger unexpected error paths.
39. **`limitsService` uses `Date.now()` for daily reset** – src/services/limits/limitsService.ts: Using server clock for daily limit windows means limits reset at different times across timezones. A user can cross midnight UTC to double their daily allowance in a single user-perceived day.
40. **`basketService` weights don't sum to 10000 bps** – src/services/basket/basketService.ts: No startup or update validation ensures basket currency weights sum to exactly `BASIS_POINTS` (10,000). A config error could allocate more or less than 100% of reserves.
41. **Investment withdrawal delay uses server-local clock** – src/services/investment/: The 24-hour withdrawal delay for retail / calendar-day delay for business relies on `new Date()` on the API server. A user can bypass delays by sending requests to a server with a drifted clock.
42. **OpenAI guard in compliance may block legitimate transactions** – src/services/ai/openaiGuard.ts: If the OpenAI API is slow, down, or returns rate-limit errors, the compliance check may block or delay legitimate transactions. There is no "fail-open" mode for when the AI service is degraded.
43. **`recoveryService` sends plaintext recovery codes via email** – src/services/recovery/recoveryService.ts: Guardian recovery codes or links sent by email may be transmitted over unencrypted SMTP and stored in the recipient's inbox in plaintext.
113. **`helmet.crossOriginOpenerPolicy` not set** – src/index.ts: The `Cross-Origin-Opener-Policy` header is not set. Combined with `crossOriginIsolated`, missing COOP enables cross-origin attacks like `window.opener` manipulation.
114. **No `helmet.crossOriginEmbedderPolicy` for Spectre protection** – src/index.ts: Without `Cross-Origin-Embedder-Policy: require-corp`, the API responses can be embedded in cross-origin contexts, enabling side-channel attacks (Spectre, Meltdown) on shared hosting.
115. **Prisma `@@map` and `@map` naming not consistent with database conventions** – prisma/schema.prisma: Some models use camelCase for mapped table/column names while others use snake_case. Database operators writing raw SQL must remember which convention applies to which table.
116. **No database connection string rotation for credential changes** – src/config/database.ts: The database password is read once at startup from env vars. If credentials are rotated while the process is running, the next connection attempt fails and the process crashes without re-reading the env var.
117. **`axios` interceptors do not retry on 5xx with `Retry-After` header** – src/services/http/client.ts: The shared HTTP client does not respect `Retry-After` headers on 429 or 503 responses. Immediate retries hit the degraded service harder and violate rate-limit policies.
118. **No `Referrer-Policy` header set** – src/middleware/securityHeaders.ts: Without `Referrer-Policy`, browsers send full URLs in the `Referer` header when users click links from the API's error pages or documentation, leaking internal URLs and query parameters to external sites.
119. **`helmet.dnsPrefetchControl` may not be aligned with CDN needs** – src/index.ts: If the app uses a CDN for static assets, disabling DNS prefetch (`X-DNS-Prefetch-Control: off`) adds round-trip latency for CDN domain resolution on every page load.
120. **No structured request logging for audit compliance** – src/middleware/requestLogger.ts: Request logs may not include all required fields for financial audit (user ID, IP, action type, resource ID, timestamp with microsecond precision, request body hash). Audit findings cite incomplete log data.
121. **Environment-specific config not validated on startup** – src/config/index.ts: Config values from env vars are not validated at startup with a schema (Zod, joi, convict). An invalid `PORT` (e.g., `3000a`) causes the server to fail silently on `listen()` with a cryptic `EADDRNOTAVAIL` or `EINVAL`.
122. **`process.on('uncaughtException')` handler missing or logs but doesn't restart** – src/index.ts: The uncaught exception handler may log the error and continue. The process is in an undefined state after an uncaught exception; continuing may corrupt data or serve incorrect responses.
123. **No memory usage monitoring or heap dump on leak detection** – src/index.ts: There is no `--max-old-space-size` set and no heap usage metric exported. A slow memory leak from cached data or unclosed streams takes the server down after hours/days with no alert.
124. **Prisma `findMany` without `take` on unbounded collections** – src/services/transaction/transactionService.ts: Some query paths may call `prisma.transaction.findMany({ where: { userId } })` without a `take` limit. A user with 100K+ transactions triggers a query that returns the entire table and OOMs the process.
125. **No `User-Agent` filtering or bot blocking on API endpoints** – src/middleware/userAgentFilter.ts: API endpoints are accessible to any User-Agent. Malicious scanners, credential-stuffing tools, and broken scripts consume resources and pollute metrics with no recourse.
126. **`crypto.randomUUID()` used for IDs instead of sortable UUIDs (UUIDv7)** – src/utils/idGenerator.ts: Using `crypto.randomUUID()` (UUIDv4) for primary keys causes index fragmentation in PostgreSQL B-tree indexes. UUIDv7 (timestamp-ordered) improves insert performance and index locality.
127. **No `ETag` or `Last-Modified` on static/swagger file serving** – src/routes/swagger.ts: Swagger UI static assets (JS, CSS, HTML) are served without conditional request headers. Browsers re-download the full swagger-ui bundle on every page load, wasting bandwidth.
128. **`express.json({ verify })` raw body not preserved for webhook signature verification** – src/controllers/webhookController.ts: If `express.json()` parses the body before webhook signature verification, the raw body needed for HMAC verification is lost. The verify function must capture `req.rawBody`.
129. **No `Content-Disposition` header on file download endpoints** – src/controllers/reportController.ts: Transaction report exports may serve files without a `Content-Disposition` header. Browsers render the CSV/PDF inline or save it with a generic `download` filename rather than `acbu_statement_2025-06.csv`.
130. **`express.Router()` case-sensitive routing not configured** – src/routes/index.ts: Express routers may not set `caseSensitive: true`. Routes like `/API/V1/Mint` and `/api/v1/mint` are treated identically, which may bypass middleware mounted on the lowercase path.
131. **No test for simultaneous mint and burn on same account** – tests/integration/: There is no test that mints and burns in rapid succession for the same user. The contract sequence number may be stale for the second transaction, causing `tx_bad_seq`.
132. **No test for large payload response (>1MB) compression behavior** – tests/integration/: Compression middleware behavior with jumbo responses (transaction history with 10K+ entries) is untested. The response may be sent uncompressed or trigger a zlib memory allocation failure.
133. **`dotenv` loaded after some imports that read `process.env`** – src/index.ts: If `dotenv.config()` is called after modules that read `process.env` at import time, those modules get undefined values. Import order is fragile and not enforced by tests or linter.
134. **No `package.json` `files` field, `dist/` published with unnecessary files** – package.json: Without a `files` field, `npm publish` includes everything not in `.gitignore`. The published package may contain `src/` (TypeScript), `tests/`, `prisma/`, and local config files.
135. **`jest.setup.ts` or `beforeAll` seeds database but doesn't clean up in `afterAll`** – tests/setup.ts: Integration test setup seeds test data but `afterAll` cleanup may be missing or inside a `try-catch` that silently swallows cleanup failures. Subsequent test runs collide with leftover data.
136. **No `Content-Length` validation against actual body size** – src/middleware/bodyParser.ts: The server trusts `Content-Length` without verifying the actual body size matches. A mismatch between declared and actual size can crash body parsers or truncate request data silently.
137. **`engines` field missing `pnpm` or `npm` version constraint** – package.json: The `engines` field specifies Node version but not the package manager. A CI runner using npm instead of pnpm installs incorrect dependencies or generates a different lockfile.

## Trivial

44. **Console.log used alongside Winston logger** – Multiple files: `console.log` or `console.error` calls in production code bypass log level configuration and structured logging format.
45. **Unused Zod schemas in validators directory** – src/validators/: Some Zod validation schemas may be defined but not imported by any route or controller, indicating dead code or incomplete wiring.
46. **Hardcoded Stellar network passphrase** – src/config/contracts.ts or src/services/stellar/: The Stellar network passphrase ('Test SDF Network ...' for testnet) may be hardcoded instead of read from env. Deploying to mainnet with testnet passphrase causes all transactions to fail.
47. **Nodemon watches `dist/` directory** – nodemon.json: If `dist/` is in the watch list, `tsc` compilation triggers a restart loop. The watch list should be limited to `src/`.
48. **No `.dockerignore` for node_modules** – Project root: If `.dockerignore` is missing, the Docker build context includes `node_modules/`, `dist/`, `logs/`, and `.env`, bloating the image and potentially leaking secrets.
49. **Seed script does not clean up after itself** – prisma/seed.ts: The seed script may insert test users, orgs, and transactions without a `--truncate` flag. Re-running the seed duplicates data instead of resetting to a known state.
50. **`tsconfig.build.json` may not exclude test files** – tsconfig.build.json: Test files may be included in the `dist/` output, shipping `*.test.ts` and `*.spec.ts` to production with mock secrets and test data.
